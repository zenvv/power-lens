# BYOK: explicação por IA com chave do próprio usuário (Fase 6)

## O quê

- `apps/web/src/lib/ai/providers.ts`: chamada direta do browser pra Anthropic e Gemini
  (sem backend, sem proxy) — `AiSettingsDialog` e `AiExplanationCard` novos em
  `apps/web/src/components/ai/`, com uma nova aba "Explicação por IA" no `DocumentView`.
- `apps/web/src/lib/ai/settings-storage.ts`: provedor/modelo/chave persistidos em
  `localStorage`, nunca enviados a nenhum lugar além da chamada direta ao provedor.
- `buildPromptMd` (já existia dentro de `context-pack.ts`, usado só pro `PROMPT.md` do
  pacote de contexto) agora exportado publicamente — o BYOK reusa exatamente o mesmo texto
  de instrução, só que chamado automaticamente em vez de colado à mão num LLM.
- Corrigido `apps/web/src/components/ui/button.tsx` pra usar `React.forwardRef` — sem
  isso, `<DialogTrigger asChild><Button>...` (primeiro uso de `asChild` com uma ref real no
  projeto) disparava um warning do React 18 ("function components cannot be given refs").
  Achado testando o fluxo de configuração no browser.

## Por quê

Fase 6 do roadmap — última peça do MVP funcional (spec seção 10).

## Decisões

- **OpenAI de fora do seletor**: verificado antes de escrever qualquer código que a API da
  OpenAI (`api.openai.com`) não devolve `Access-Control-Allow-Origin`, ou seja, não dá pra
  chamar direto do browser sem um backend/proxy intermediário — o que contrariaria o
  princípio "client-side only, sem servidor" do projeto. Confirmado o oposto pra Anthropic
  (header `anthropic-dangerous-direct-browser-access: true`) e Gemini (endpoint REST
  simples `generateContent`, sem headers extras). Pergunta feita ao usuário antes de
  decidir: manter só Anthropic + Gemini funcionando de verdade, com a OpenAI aparecendo
  desabilitada no seletor com uma nota explicando o motivo, em vez de incluir uma opção que
  falharia sempre.
- **Validado com uma chave falsa contra a API real do Gemini** (não só mockado): o
  pipeline completo — fetch direto do browser, sem CORS bloqueando, parse do erro —
  funcionou de ponta a ponta, retornando a mensagem de erro genuína do provedor ("API key
  not valid. Please pass a valid API key.") na UI. Confirma que a pesquisa de CORS estava
  certa e que o tratamento de erro é honesto (mostra o erro real do provedor, não um erro
  genérico).
- **Modelo é um campo de texto livre, não uma lista fixa**: em vez de hardcodar um ID de
  modelo que fica desatualizado com o tempo, o campo vem pré-preenchido com um default
  razoável (`gemini-2.5-flash`, `claude-sonnet-4-5`) mas é editável — evita a app quebrar
  silenciosamente quando um provedor descontinua um modelo.
- **Reaproveitado o mesmo prompt do pacote de contexto** (`buildPromptMd`) em vez de
  escrever um novo: a chamada automática ao provedor é conceitualmente só a versão
  automatizada de "cole `PROMPT.md` e `ir.json` num LLM", então merece o mesmo texto.
